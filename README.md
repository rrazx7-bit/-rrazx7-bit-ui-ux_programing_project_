# 모아봄

여러 수업의 과제와 마감일을 정리하는 웹 서비스입니다. 해야 할 일의 계획을 세워 내 과제 목록에 모으고, 마감과 진행 상태를 확인할 수 있습니다.

[웹페이지 열기](https://rrazx7-bit.github.io/-rrazx7-bit-ui-ux_programing_project_/) · [프로젝트 저장소](https://github.com/rrazx7-bit/-rrazx7-bit-ui-ux_programing_project_)

## 사용자와 목표

- 주요 사용자: 여러 수업의 과제와 마감일을 정리하려는 대학생
- 서비스 목적: 흩어진 할 일을 이름과 마감으로 정리하고, 남은 과제와 끝낸 과제를 구분하기
- 핵심 행동: 과제 계획을 확정해 목록에 추가하고, 다시 열어 내용을 확인하거나 완료 상태를 바꾸기
- 완료 조건: 확정한 이름·과목·마감이 내 과제 목록에 저장되고, 다시 연 항목의 상태를 바꾸면 목록과 상세 내용이 함께 갱신되기

목록에 추가한 과제는 이 브라우저에 저장됩니다. 작성 중인 계획, 미리보기와 이메일 입력 상태는 새로고침하면 초기화됩니다. 다른 기기와의 동기화와 실제 알림 발송은 지원하지 않습니다.

## 입력 흐름 개선

과제 이름의 조건과 글자 수를 입력창 가까이에서 확인하도록 바꾸고, 계획 입력부터 목록 저장까지 하나의 폼으로 연결했습니다. 저장 중에는 중복 제출을 막고, 저장에 실패하면 작성한 내용을 유지한 채 다시 시도할 수 있습니다.

이름이 너무 짧거나 비어 있을 때 수정 방법을 바로 알 수 있도록 안내를 나눴습니다. 오류 표시도 아무 글자나 입력하면 없어지던 방식에서 조건을 충족했을 때 해제하는 방식으로 바꿨습니다. 저장 실패를 완료로 오해하지 않도록 새 과제는 브라우저 저장이 성공한 뒤에만 목록에 추가합니다.

## 사용자 흐름

과제 계획 세우기 → 과제 입력 → 마감 선택 → 내용 확인·확정 → 내 과제에 추가 → 목록에서 다시 열기

1. **진입:** 미리 체험의 ‘과제 계획 세우기’를 누릅니다. 미리 적은 이름이 있으면 첫 입력창에 가져옵니다. 목록의 ‘새 계획 세우기’에서는 빈 계획으로 시작합니다.
2. **입력:** 과제 이름을 적고, 필요하면 과목도 입력합니다. 글자 수와 조건 충족 안내를 확인하고 다음 단계로 이동합니다.
3. **선택:** ‘마감일 지정’ 또는 ‘마감일 없이 시작’을 고릅니다. 마감일을 지정할 때만 날짜를 입력합니다.
4. **확인:** 이름·과목·마감을 검토합니다. 이전 단계로 돌아가 수정하거나 확인 창에서 계획을 확정합니다. ‘다시 확인’과 Escape는 값을 유지한 채 창을 닫습니다.
5. **저장:** 정리한 계획에서 ‘내 과제에 추가’를 누릅니다. 저장 중 안내가 나오고, 성공하면 ‘내 과제 목록 보기’로 이동할 수 있습니다. 실패하면 같은 내용으로 다시 저장하거나 ‘내용 수정하기’로 돌아갑니다.
6. **다음 계획:** ‘새 계획 세우기’는 입력값·오류·글자 수·요약·저장 안내와 버튼 상태를 초기화합니다. 이미 저장한 목록은 그대로 둡니다.

## 입력 조건과 안내

| 항목 | 입력 조건 | 안내와 반응 |
| --- | --- | --- |
| 과제 이름 | 필수. 앞뒤 공백을 제외하고 2자 이상, 입력 전체는 60자 이내 | 입력한 그대로의 글자 수를 표시합니다. 빈 값·공백만 있는 값과 한 글자의 오류를 구분하고, 조건에 맞으면 ‘입력 조건을 충족했어요.’를 보여 줍니다. |
| 과목 | 선택. 입력하면 30자 이내 | 비워 둘 수 있다는 도움말을 표시합니다. 빈 값은 요약에 ‘미지정’으로 나타납니다. |
| 마감 방식 | ‘마감일 지정’ 또는 ‘마감일 없이 시작’ 중 하나 선택 | 선택하지 않으면 방식을 고르라는 안내를 표시합니다. |
| 마감일 | 마감일 지정 시 필수. 실제 날짜이며 연도는 네 자리까지 | 지정할 때만 표시·활성화합니다. 마감일 없이 시작으로 바꾸면 날짜 값과 오류를 지우고 숨김·비활성화하여 제출값에서 제외합니다. |

각 항목은 `label`과 입력 요소를 연결하고, `aria-describedby`로 도움말·오류를 함께 읽도록 했습니다. 날짜 영역은 `aria-controls`, `aria-expanded`, `hidden`, `disabled`, `required`를 같은 선택값에 맞춰 갱신합니다. 상태는 색뿐 아니라 문구로도 표시합니다.

## 제출과 결과 처리

| 사용자 행동 | 확인할 조건 | 화면 반응 | 다음 행동 |
| --- | --- | --- | --- |
| 다음 단계로 이동 | 현재 단계의 필수 값과 길이가 맞는지 | 조건이 맞으면 다음 단계로 이동합니다. 잘못된 값은 수정 방법을 표시하고 첫 오류 입력칸에 초점을 둡니다. | 입력 수정 또는 다음 단계 |
| 오류가 난 이름 수정 | 수정한 값이 2자 이상·60자 이내인지 | 아직 잘못된 값이면 오류를 유지하고, 올바르게 고치면 문구·오류 스타일·`aria-invalid`를 함께 해제합니다. | 계속 입력 |
| 계획 확정 또는 내 과제에 추가 | 이름·과목·마감 조건을 다시 충족하는지 | 이전 단계에서 문제가 발견돼도 해당 단계를 열고 첫 오류로 이동합니다. | 오류 수정 후 다시 진행 |
| 내 과제에 추가 | 필요한 값이 모두 유효하고 저장 중이 아닌지 | ‘저장 중…’을 표시하고 입력·버튼을 잠급니다. 반복 클릭과 Enter는 추가 저장을 만들지 않습니다. | 저장 결과 기다리기 |
| 저장 성공 | 브라우저 저장이 정상적으로 끝났는지 | 진행 중 항목을 목록에 추가하고 완료 안내를 표시합니다. 추가·수정 버튼을 비활성화합니다. | 목록 보기 또는 새 계획 작성 |
| 저장 실패 | 저장 권한·용량 문제 등으로 저장할 수 없는지 | 목록에 새 항목을 만들지 않습니다. 입력·선택·요약을 유지하고 ‘다시 저장하기’와 ‘내용 수정하기’를 활성화합니다. | 저장 설정 확인 후 재시도 또는 내용 수정 |
| 같은 계획 다시 추가 | 이름·과목·마감이 모두 같은 항목이 있는지 | 중복 항목을 만들지 않고 기존 과제를 확인하도록 안내합니다. | 목록에서 다시 열기 |
| 내용 수정하기 | 아직 목록에 저장하지 않은 계획인지 | 값을 유지한 채 과제 입력으로 돌아갑니다. 수정 후에는 요약도 다시 갱신됩니다. | 계획 다시 확인 |

입력부터 완료 화면까지 `index.html`의 `plan-form` 하나에 두었습니다. 단계 이동 버튼은 `type="button"`, 확정과 저장 버튼은 `type="submit"`을 사용합니다. 버튼과 텍스트 입력의 Enter는 `script.js`의 `handlePlanSubmit()`으로 모이고, `validatePlan()`에서 검사한 뒤 `collectPlan()`의 `FormData`로 현재 값을 읽습니다.

`setPlanSubmitState()`는 저장 중·성공·실패 문구, 버튼 비활성화와 폼의 `aria-busy`를 함께 바꿉니다. `addPlanToList()`는 저장 안내가 보이도록 짧게 기다린 뒤 `persistSavedTasks()`의 결과를 확인합니다. `localStorage.setItem()`이 예외를 내면 입력을 유지하고 재시도를 허용합니다. 저장된 데이터 자체를 읽지 못한 경우에는 `loadSavedTasks()`에서 원본 덮어쓰기를 막으며, 재시도할 때 다시 읽을 수 있는지 확인합니다.

## 내 과제 목록

목록은 마감일이 가까운 순서로 보여 주며, 마감일이 없는 과제는 뒤에 둡니다. ‘전체’, ‘진행 중’, ‘완료’로 범위를 골라 볼 수 있습니다.

| 사용자 행동 | 조건과 반응 | 다음 행동 |
| --- | --- | --- |
| 상태 필터 선택 | 선택한 상태의 과제만 표시합니다. 해당 항목이 없으면 결과 없음 안내를 보여 줍니다. | 과제 다시 열기 또는 전체 과제 보기 |
| 빈 목록 확인 | 과제가 하나도 없으면 첫 계획을 만드는 안내를 보여 줍니다. | 첫 계획 세우기 |
| 다시 열기 | 저장한 이름·과목·마감·현재 상태를 상세 화면에 표시합니다. | 완료 표시, 진행 중으로 변경, 삭제 또는 닫기 |
| 완료로 표시·진행 중으로 되돌리기 | 상세 상태·목록·개수를 함께 바꾸고 저장합니다. 현재 필터에 맞지 않으면 목록에서 빠집니다. | 상태에 맞는 목록 확인 |
| 삭제 선택 | 바로 지우지 않고 삭제 여부를 확인합니다. 계속 보관과 Escape는 항목을 유지합니다. | 삭제 확정 또는 계속 보관 |
| 삭제 확정 | 선택한 항목만 제거합니다. 마지막 항목을 지우면 빈 목록 안내로 바뀝니다. | 다른 과제 확인 또는 새 계획 작성 |
| 상세 화면 닫기 | 목록으로 돌아가 조작하던 버튼에 초점을 둡니다. 해당 버튼이 없으면 목록 제목으로 이동합니다. | 다음 과제 확인 |

목록은 `localStorage`의 `moabom.tasks.v1`에 저장합니다. 같은 브라우저에서 새로고침해도 항목과 완료 상태를 다시 불러오며, 사이트 데이터를 지우면 목록도 사라집니다. 서버나 계정에 전송하지 않습니다.

새 과제 추가는 저장 성공 후 반영합니다. 기존 항목의 완료 상태 변경·삭제가 저장에 실패하면 현재 화면의 변경은 유지하지만, 새로고침 시 보존되지 않을 수 있다는 안내를 표시합니다. 읽지 못한 기존 데이터는 새 데이터로 덮어쓰지 않습니다.

## 함께 사용할 수 있는 기능

- 과제 적기·마감 확인·완료 표시 탭과 과제 이름의 실시간 미리보기
- 완료 체크·해제, 다시 진행하기, 예시 넣기
- 상단 메뉴를 통한 페이지 내부 이동
- 빈 입력·형식 오류·확인 완료를 구분하는 이메일 형식 확인

미리보기 탭의 과목과 마감일은 예시입니다. 이메일은 형식만 확인하며 저장하거나 전송하지 않습니다. 입력한 내용을 화면에 반영할 때는 `textContent`를 사용해 HTML로 해석하지 않습니다.

## 화면과 키보드 조작

768px 이하에서는 메뉴·탭·입력 영역과 버튼을 세로로 배치합니다. 긴 과제 이름과 안내 문장은 줄바꿈합니다. 단계가 바뀌면 다음 입력창이나 제목으로 초점을 옮기고, 오류가 있으면 첫 오류 항목으로 이동합니다.

Tab으로 조작 요소를 이동하고 Enter로 입력을 진행할 수 있습니다. 한글 조합 중 Enter는 제출로 처리하지 않습니다. 탭은 넓은 화면에서 좌우, 좁은 화면에서 위아래 방향키로 전환합니다. 확인 창에서는 Tab으로 버튼 사이를 이동하며 Escape로 취소할 수 있습니다.

## 확인 순서

1. **빈 값과 짧은 값:** 과제 계획을 열고 빈 값·공백·한 글자로 다음 단계에 진입합니다. 오류 문구와 초점 위치를 확인합니다.
2. **입력 중 피드백:** 오류 상태에서 한 글자를 입력하면 오류가 유지되는지 확인합니다. 두 글자와 60자를 입력해 글자 수·조건 충족 안내·오류 해제를 확인합니다.
3. **조건부 날짜:** 마감일 지정을 선택하고 날짜 없이 진행합니다. 오류를 확인한 뒤 날짜를 채웁니다. 마감일 없이 시작으로 바꿔 날짜가 숨겨지고 비활성화되며 제출값에서 빠지는지 확인합니다.
4. **수정과 확정:** 이전 단계로 돌아가도 값이 남는지 확인합니다. 이름과 날짜를 바꾼 뒤 요약에 반영되는지, 확인 창 취소와 재확정이 동작하는지 확인합니다.
5. **정상 저장:** 내 과제에 추가를 누릅니다. 저장 중 버튼이 잠기는지, 반복 조작해도 하나만 추가되는지 확인합니다. 목록을 다시 열고 새로고침해도 값이 남는지 확인합니다.
6. **저장 실패와 재시도:** 브라우저 검사에서 저장 공간 부족 예외를 발생시켜 실패 안내·값 보존·버튼 재활성화를 확인합니다. 예외를 해제한 뒤 같은 내용으로 재시도해 항목 하나만 저장되는지 확인합니다. 저장 데이터가 손상된 경우 원본을 덮어쓰지 않는지도 확인합니다.
7. **다시 작성:** 새 계획 세우기를 눌러 입력·글자 수·오류·성공 안내·버튼·진행 상태가 초기화되고 기존 목록은 남는지 확인합니다.
8. **화면과 기존 기능:** 1100·769·768·390px에서 입력창·버튼·안내가 잘리거나 겹치지 않는지 확인하고, 목록 필터·상태 변경·삭제·탭·이메일 확인도 함께 검사합니다.

- **조건부 날짜:** 마감일 지정 시에만 날짜가 표시·활성화됐습니다. 마감일 없이 시작으로 바꾸면 값과 오류가 지워지고 `FormData`에서도 제외됐습니다.
- **최종 검사:** 최종 저장 시 이전 단계의 값이 잘못돼 있어도 해당 입력 단계로 돌아가 수정할 수 있었습니다. 이전 이동·확인 취소·내용 수정에서는 입력값이 유지됐습니다.
- **저장 중과 중복:** 저장 중에는 버튼이 잠기고 `aria-busy`가 바뀌었습니다. 제출을 반복해도 저장은 한 번만 실행됐습니다.
- **실패와 재시도:** 저장 공간 부족 예외를 발생시켰을 때 실패 안내와 재시도 버튼이 나타났습니다. 새 항목은 추가되지 않았고, 입력값을 유지한 채 재시도하자 한 항목만 저장됐습니다. 새로고침 후에도 저장 결과가 남았습니다.
- **원본 보호:** 손상된 저장 데이터는 덮어쓰지 않았습니다. 데이터를 복구한 뒤 재시도하면 기존 항목을 유지하면서 새 계획이 저장됐습니다.
- **초기화와 기존 기능:** 새 계획은 입력·글자 수·오류·저장 안내·버튼 상태를 초기화했고 기존 목록은 유지했습니다. 목록 추가·다시 열기·필터·상태 변경·삭제·취소와 기존 탭·이메일 확인도 통과했습니다.

검사 중 JavaScript·콘솔 오류와 가로 넘침은 없었습니다. 네 너비의 실제 스크린샷에서 입력 오류·조건 충족·날짜 입력·저장 중·실패 안내가 잘리거나 겹치지 않는 것도 확인했습니다. 배포된 HTML·CSS·JavaScript가 검사 대상 저장소 코드와 일치하는 것도 확인했습니다.
