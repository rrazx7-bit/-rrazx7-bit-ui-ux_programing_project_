# 모아봄

여러 수업의 과제와 마감일을 한곳에서 정리하는 웹 서비스입니다. 마감이 가까운 일부터 확인하고, 끝낸 과제를 표시하며 남은 일정을 살펴볼 수 있도록 만들고 있습니다.

## 만들고 있는 기능

- 과목별로 과제와 마감일 모아 보기
- 마감이 가까운 순서로 오늘 할 일 정하기
- 완료한 과제와 남은 과제 구분하기

현재는 서비스 소개 페이지, 과제 이름과 완료 상태를 바꿔 볼 수 있는 미리보기, 이메일 형식 확인 기능을 구현했습니다. 과제를 여러 개 등록하거나 저장하는 기능과 실제 알림 신청 기능은 아직 개발 전입니다.

## 페이지 구성

서비스 소개, 주요 기능, 미리 체험, 이용 방법, 시작 알림 순서로 구성했습니다. 기능을 읽은 뒤 직접 과제 이름을 적고 완료 상태를 바꿔 볼 수 있도록 했습니다. 상단 메뉴에서 원하는 항목으로 바로 이동할 수도 있습니다.

## 과제 미리보기

설명만으로는 사용 흐름을 알기 어려워 ‘과제 적기’, ‘마감 확인’, ‘완료 표시’를 직접 전환하는 화면을 추가했습니다. 과제 이름 하나를 세 화면에서 함께 사용하므로, 입력한 내용이 마감 목록과 완료 카드에 어떻게 보이는지 확인할 수 있습니다.

| 조작 | 이벤트 | 화면 변화 |
| --- | --- | --- |
| 예시 넣기 | `click` | 과제 이름과 글자 수, 카드 색상이 바뀌고 버튼이 ‘예시 적용됨’으로 비활성화됩니다. 이름을 수정하면 다시 누를 수 있습니다. |
| 과제 이름 입력·삭제 | `input` | 30자 이내의 이름과 글자 수를 즉시 반영합니다. 이름이 있으면 카드가 강조되고 완료 체크를 사용할 수 있습니다. 빈칸이면 완료 상태를 지웁니다. |
| 완료 체크·해제 | `change` | 안내 문구, 카드 배경과 취소선, ‘다시 진행하기’ 버튼 상태가 함께 바뀝니다. 마감 목록의 진행 상태도 맞춰 바꿉니다. |
| 다시 진행하기 | `click` | 완료 체크와 강조를 해제하고 진행 중 안내로 돌아갑니다. 버튼은 다시 비활성화됩니다. |
| 세 기능 탭 선택 | `click` | 선택한 버튼을 강조하고 해당 화면 하나만 보여 줍니다. 입력값과 완료 상태는 탭을 이동해도 유지됩니다. |

JavaScript는 `textContent`로 문구를 바꾸고, `classList`로 CSS 상태를 연결하며, `disabled`로 조작 가능한 상태를 맞춥니다. 탭과 패널은 `querySelectorAll`로 모아 `forEach`로 함께 갱신합니다.

키보드에서는 Tab으로 선택된 탭에 진입하고 방향키로 전환할 수 있습니다. 넓은 화면에서는 좌우, 768px 이하에서는 위아래 방향키를 사용합니다. Home과 End는 처음과 마지막 탭으로 이동하며, Enter와 Space로 버튼을 누를 수도 있습니다. 안내는 `aria-live`, 탭 선택은 `aria-selected`로 전달합니다.

미리보기의 과목과 마감일은 예시입니다. 입력값과 완료 표시는 저장하지 않으며 새로고침하면 초기화됩니다.

## 화면 크기에 따른 배치

기존에는 390px처럼 좁은 화면에서도 제목이 60px로 표시되고, 메뉴와 입력 폼은 가로 배치를 유지한 채 남는 공간에 따라 줄바꿈했습니다. 제목이 차지하는 공간을 줄이고 메뉴부터 입력창까지 일정한 순서로 읽을 수 있도록 모바일 배치를 정리했습니다.

`.feature-list`를 CSS Grid로 바꾸고 `repeat(auto-fit, minmax(260px, 1fr))`을 적용했습니다. 넓은 화면에서는 세 기능을 나란히 비교하고, 공간이 줄면 카드의 열 수가 자동으로 바뀝니다. `@media (max-width: 768px)`에서는 메뉴와 폼에 `flex-direction: column`, 기능 목록에 `grid-template-columns: 1fr`을 적용해 모두 한 열로 배치했습니다.

768px 이하에서는 제목을 36px로 줄이고 바깥 여백을 16px로 맞췄습니다. 이메일 입력창과 버튼은 `width: 100%`로 같은 폭을 사용하며, 버튼 높이는 52px 이상으로 유지해 누를 공간을 확보했습니다. 콘텐츠의 유동 너비와 이미지의 `width: 100%`, `max-width`로 화면 안에서 크기가 조절되도록 했습니다.

1100·769·768·390px에서 기능 카드는 각각 3열·2열·1열·1열로 표시됩니다. 미리보기 탭은 768px 이하에서 세로로 쌓이고, 과제 입력창과 카드도 한 열로 바뀝니다.

## 동작 확인

2026-10-09에 저장소 코드와 GitHub Pages 배포 페이지를 Chromium으로 각각 확인했습니다. 화면 배치·이메일 확인과 과제 미리보기 검사를 네 너비에서 실행해 총 16개가 통과했습니다.

| 화면 너비 | 미리보기 탭 | 저장소 코드 / 배포 페이지 |
| --- | --- | --- |
| 1100px | 가로 3개 | 모두 통과 |
| 769px | 가로 3개 | 모두 통과 |
| 768px | 세로 3개 | 모두 통과 |
| 390px | 세로 3개 | 모두 통과 |

입력·삭제·30자 제한, 예시 넣기, 완료 체크·해제, 다시 진행하기, 탭 전환과 새로고침 초기화를 확인했습니다. 탭과 표시 패널은 항상 하나씩 유지됐고, Tab·방향키·Home·End·Enter·Space 조작도 정상 동작했습니다. 기존 메뉴 이동과 이메일의 빈 입력·형식 오류·확인 완료도 통과했습니다.

검사 중 JavaScript·콘솔 오류와 가로 넘침은 없었습니다. 배포된 HTML·CSS·JavaScript가 저장소 코드와 일치하는 것도 확인했습니다. [화면·동작 검사 결과](https://github.com/rrazx7-bit/-rrazx7-bit-ui-ux_programing_project_/actions/runs/37867775494)에서 각 상태의 스크린샷과 보고서를 내려받을 수 있습니다.

## 실행 방법

저장소를 내려받은 뒤 `index.html`을 브라우저에서 열면 됩니다. 이미지가 함께 표시되도록 폴더 구조를 유지해 주세요.

HTML, CSS, JavaScript와 SVG로 작성했으며, 별도 설치나 빌드 과정은 없습니다. 화면 스타일은 `style.css`, 탭·과제 미리보기·이메일 확인 동작은 `script.js`에서 수정할 수 있습니다.

## 이메일 확인

이메일을 비워 두거나 형식에 맞지 않게 입력하면 입력창 아래에 수정할 내용을 표시합니다. 정상 형식이면 입력한 주소와 확인 완료 문구를 보여 주고 버튼을 비활성화합니다. 주소를 바꾸면 다시 확인할 수 있습니다.

`submit` 이벤트에서 새로고침을 막고, 입력값과 확인 상태에 따라 문구·색상·버튼 상태를 함께 바꿉니다. 입력한 내용을 유지한 채 결과를 확인할 수 있도록 했습니다. 주소는 저장하거나 전송하지 않으며, 새로고침하면 확인 상태도 초기화됩니다.
