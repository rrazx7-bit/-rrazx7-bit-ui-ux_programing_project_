# 모아봄

여러 수업의 과제와 마감을 한곳에 모아 두는 대학생용 웹 서비스입니다. 과제 이름과 마감일을 정해 목록에 담고, 끝낸 과제를 완료로 표시하면 남은 일만 골라 볼 수 있습니다.

[모아봄 열기](https://rrazx7-bit.github.io/-rrazx7-bit-ui-ux_programing_project_/) · [프로젝트 저장소](https://github.com/rrazx7-bit/-rrazx7-bit-ui-ux_programing_project_)

## 어디로 이동할 수 있나요?

과제 하나를 적으려고 미리 체험을 거치지 않아도 되도록 상단에 **과제 계획**을 추가했습니다. 메뉴는 스크롤해도 화면 위에 남습니다. ‘내 과제’에서는 이전의 드롭다운 대신 세 가지 상태를 버튼으로 나란히 보여 줍니다. 현재 어느 목록을 보고 있는지 알 수 있고 다른 상태도 한 번에 선택할 수 있습니다.

| 메뉴 | 주소 끝부분 | 도착하면 할 수 있는 일 |
| --- | --- | --- |
| 서비스 소개 | `#about` | 모아봄의 용도와 과제 목록 예시를 봅니다. |
| 주요 기능 | `#features` | 과제 모으기, 마감순 정리, 완료 표시가 어떻게 쓰이는지 살펴봅니다. |
| 미리 체험 | `#tryout` | 이름을 입력하고 탭을 바꿔 마감·완료 카드의 모습을 미리 봅니다. |
| 과제 계획 | `#plan-flow` | 이름·과목·마감을 입력합니다. 작성 중에 다른 메뉴를 다녀와도 같은 단계에서 이어갈 수 있습니다. |
| 내 과제 | `#my-tasks` | 저장한 과제를 다시 열고, 진행 상태를 바꾸거나 목록을 걸러 봅니다. |
| 이용 방법 | `#steps` | 과제 기록부터 완료 표시까지의 사용 순서를 봅니다. |
| 시작 알림 신청 | `#signup` | 알림에 쓸 이메일의 형식을 확인합니다. 실제 신청이나 발송은 하지 않습니다. |

현재 메뉴는 짙은 배경과 밑줄로 표시하고 해당 링크에만 `aria-current="location"`을 둡니다. 메뉴로 이동하면 주소에 목적지가 남으므로 새로고침하거나 뒤로·앞으로 가기를 해도 그 영역을 다시 엽니다. 휠·터치·키보드로 직접 스크롤할 때는 보이는 영역에 맞춰 표시와 주소만 바꾸고 방문 기록을 추가하지 않습니다. `#plan-flow`를 새로고침하면 입력 화면은 다시 열리지만 저장하지 않은 초안은 비어 있습니다.

**769px 이상**에서는 메뉴가 항상 보입니다. **768px 이하**에서는 현재 위치와 ‘메뉴 열기’ 버튼이 보입니다. 열면 버튼이 ‘메뉴 닫기’로 바뀌고 `aria-expanded`도 `false`에서 `true`로 바뀝니다. 목적지를 고르면 메뉴가 닫히고 해당 영역으로 이동합니다. 선택하지 않고 닫으려면 버튼을 다시 누르거나 Esc를 누르면 됩니다.

## 계획 입력과 저장

과제 이름의 조건과 글자 수를 입력창 곁에 두었습니다. 오류가 난 뒤에는 아무 글자나 입력했다고 안내를 지우지 않고, 실제로 조건을 충족했을 때 해제합니다.

| 입력 항목 | 조건 |
| --- | --- |
| 과제 이름 | 필수. 앞뒤 공백을 제외하고 2자 이상, 전체 60자 이내입니다. 빈 값·공백과 한 글자의 오류 문구가 다릅니다. |
| 과목 | 선택. 입력한다면 30자 이내입니다. 비워 두면 요약에 ‘미지정’으로 표시합니다. |
| 마감 방식 | ‘마감일 지정’ 또는 ‘마감일 없이 시작’ 중 하나를 고릅니다. |
| 마감일 | 지정할 때만 날짜 입력창이 나타나며 날짜가 필수입니다. ‘마감일 없이 시작’으로 바꾸면 날짜와 오류를 지우고 입력창을 비활성화해 저장값에서 제외합니다. |

‘이전’이나 확인 창의 ‘다시 확인’은 값을 유지합니다. 계획을 확정하고 **내 과제에 추가**를 누르면 마지막으로 입력 조건을 검사합니다. 잘못된 값은 해당 단계의 첫 오류로 안내합니다. 저장 중에는 버튼을 잠그고, 브라우저 저장에 성공한 뒤에만 목록에 과제를 추가합니다. 같은 이름·과목·마감의 과제는 두 번 추가하지 않습니다. ‘새 계획 세우기’는 초안과 안내를 비우고 기존 목록을 남깁니다.

저장 권한이나 용량 문제로 실패하면 입력값을 그대로 두고 **다시 저장하기**와 **내용 수정하기**를 제공합니다. `script.js`에서 `handlePlanSubmit()`이 폼 제출을 받고, `validatePlan()`이 입력을 검사합니다. `addPlanToList()`는 `persistSavedTasks()`의 저장 결과에 따라 성공 또는 재시도 상태를 표시합니다. `loadSavedTasks()`에서 기존 데이터를 읽지 못한 경우에는 원본을 덮어쓰지 않습니다.

## 내 과제의 상태 필터

| 버튼 | 표시하는 과제 |
| --- | --- |
| 전체 | 저장한 모든 과제 |
| 진행 중 | 아직 완료로 표시하지 않은 과제 |
| 완료 | 상세 화면에서 ‘완료로 표시’를 누른 과제 |

선택된 버튼에 체크 표시와 `aria-pressed="true"`를 적용하고, 나머지는 `false`로 둡니다. **N개 표시**는 현재 필터에서 보이는 카드 수입니다. 위쪽의 전체·진행 중·완료 개수는 저장된 목록 전체를 기준으로 합니다. 마감일이 빠른 과제가 먼저 나오고 기한이 없는 과제는 뒤에 나옵니다.

- 저장한 과제가 하나도 없으면 ‘아직 추가한 과제가 없어요’와 **첫 계획 세우기**가 보입니다.
- 과제는 있지만 선택한 상태에 해당하는 과제가 없으면 ‘완료한 과제가 없어요’ 또는 ‘진행 중인 과제가 없어요’가 보입니다. **전체 과제 보기**를 누르면 다른 과제를 다시 볼 수 있습니다.

카드의 ‘다시 열기’에서 진행 상태를 바꾸면 상세 내용, 카드, 개수가 함께 갱신됩니다. 현재 필터에 맞지 않게 된 과제는 그 목록에서 빠집니다. 삭제할 때는 한 번 더 확인하고, ‘계속 보관’이나 Esc로 취소할 수 있습니다.

저장한 과제는 같은 브라우저의 `localStorage`에 남습니다. 다른 기기와 동기화되지 않으며 사이트 데이터를 지우면 목록도 사라집니다. 상태 변경이나 삭제를 저장하지 못하면 현재 화면에는 반영하되 새로고침하면 사라질 수 있음을 알립니다. 미리 체험과 이메일 입력 내용은 저장하지 않습니다.

## 직접 확인하는 순서

1. **과제 계획** 메뉴로 이동합니다. 모바일에서는 ‘메뉴 열기’를 먼저 누릅니다. 선택한 뒤 주소가 `#plan-flow`로 바뀌고 모바일 메뉴는 닫힙니다.
2. 예를 들어 ‘자료 조사’를 적고 ‘마감 선택하기’ → ‘마감일 없이 시작’ → ‘계획 내용 확인하기’로 이동합니다. ‘이 계획으로 시작하기’ → ‘계획 확정’ → **내 과제에 추가**를 누릅니다.
3. **내 과제 목록 보기**를 눌러 ‘자료 조사’가 ‘진행 중’으로 표시되는지 봅니다. ‘다시 열기’에서 입력한 내용을 확인하고 ‘완료로 표시’ → ‘목록으로’를 누릅니다.
4. **진행 중 → 완료 → 전체**를 차례로 선택합니다. 방금 끝낸 과제가 ‘완료’와 ‘전체’에만 보이는지, 선택 표시와 결과 수가 카드에 맞는지 확인합니다.
5. 상단 메뉴에서 ‘이용 방법’으로 이동한 뒤 브라우저 뒤로 가기·앞으로 가기·새로고침을 해 봅니다. 주소, 현재 메뉴, 도착 영역이 함께 바뀌는지 확인합니다.

## 테스트 결과

**메뉴와 목록 탐색 (2026-11-06)** — Chromium에서 1100·769·768·390px 각각으로 저장소 코드와 배포 페이지를 열었습니다. 각 환경에서 9개씩, 총 72개 검사가 통과했습니다. 배포된 HTML·CSS·JavaScript는 검사한 저장소 파일과 일치했습니다.

- ‘과제 계획’으로 직접 이동하고 다른 메뉴를 다녀와도 같은 페이지에서는 초안이 유지됐습니다. 새로고침·뒤로·앞으로 가기에서 목적지와 현재 링크가 일치했고, 키보드로 문서 끝까지 스크롤해도 방문 기록 수가 늘지 않았습니다.
- 768px 이하에서 메뉴를 열고 키보드로 목적지를 선택하면 메뉴가 닫히고 본문으로 초점이 이동했습니다. Esc로 닫으면 초점이 메뉴 버튼으로 돌아왔습니다. 768↔769px로 화면을 바꿔도 보이는 메뉴와 버튼 상태가 일치했습니다.
- 새 계획을 저장하고 상세 화면에서 완료로 바꾸자 ‘완료’ 필터에 카드 1개가 표시됐습니다. 완료한 과제가 없을 때는 ‘0개 표시’와 ‘전체 과제 보기’가, 아무 과제도 저장하지 않았을 때는 ‘첫 계획 세우기’가 표시됐습니다.
- 기존 입력 오류 수정, 저장 실패 후 재시도, 목록 상세·삭제, 미리 체험과 이메일 확인도 함께 통과했습니다.
