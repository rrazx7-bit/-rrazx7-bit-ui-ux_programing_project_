# 모아봄

여러 수업의 과제와 마감일을 정리하는 웹 서비스입니다. 해야 할 일의 계획을 세워 내 과제 목록에 모으고, 마감과 진행 상태를 확인할 수 있습니다.

[웹페이지 열기](https://rrazx7-bit.github.io/-rrazx7-bit-ui-ux_programing_project_/) · [프로젝트 저장소](https://github.com/rrazx7-bit/-rrazx7-bit-ui-ux_programing_project_)

## 사용자와 목표

- 주요 사용자: 여러 수업의 과제와 마감일을 정리하려는 대학생
- 서비스 목적: 흩어진 할 일을 이름과 마감으로 정리하고, 남은 과제와 끝낸 과제를 구분하기
- 핵심 행동: 과제 계획을 확정해 목록에 추가하고, 다시 열어 내용을 확인하거나 완료 상태를 바꾸기
- 완료 조건: 확정한 이름·과목·마감이 내 과제 목록에 반영되고, 다시 연 항목의 상태를 바꾸면 목록과 상세 내용이 함께 갱신되기

이전에는 과제 계획을 확정한 뒤 완료 화면에서만 확인할 수 있었습니다. 이제 확정한 계획을 내 과제 목록에 추가해 다시 열고, 진행 상태를 바꾸거나 필요한 항목만 골라 볼 수 있습니다.

목록에 추가한 과제는 이 브라우저에 저장됩니다. 작성 중인 계획, 미리보기와 이메일 입력 상태는 새로고침하면 초기화됩니다. 다른 기기와의 동기화와 실제 알림 발송은 지원하지 않습니다.

## 사용자 흐름

미리 체험에서 진입 → 과제 입력 → 마감 선택 → 내용 확인 → 완료

1. **진입:** 기존 과제 미리보기의 ‘과제 계획 세우기’를 누릅니다. 미리 적은 이름이 있으면 첫 입력창에 가져옵니다.
2. **입력:** 과제 이름을 적고, 필요하면 과목도 입력합니다. 이름은 필수이고 과목은 선택입니다.
3. **선택:** ‘마감일 지정’ 또는 ‘마감일 없이 시작’을 고릅니다. 마감일을 지정할 때만 날짜 입력이 나타납니다.
4. **확인:** 이름·과목·마감을 검토합니다. 이전 단계로 돌아가 수정하거나 확인 창에서 계획을 확정합니다.
5. **완료:** 정리한 계획을 확인한 뒤 ‘내 과제에 추가’를 눌러 목록에 보관합니다. ‘내 과제 목록 보기’로 목록을 확인하거나 ‘새 계획 세우기’로 다음 과제를 작성합니다.

확인 창은 내용 확인 단계에 포함됩니다. 화면에는 입력·선택·확인의 진행 상태를 표시하고, 완료 후에는 ‘계획 완료’로 바꿉니다.

## 인터랙션 시나리오

| 행동 | 이벤트 | 조건 | 화면 반응 | 다음 상태 |
| --- | --- | --- | --- | --- |
| 과제 계획 세우기 | `click` | 처음 진입 | 미리보기의 이름을 가져오고 입력창으로 초점을 옮깁니다. | 과제 입력 |
| 계획 이어서 보기 | `click` | 이미 시작한 계획이 있음 | 입력값을 덮어쓰지 않고 진행 중이던 화면으로 이동합니다. | 현재 단계 유지 |
| 마감 선택하기 | `submit` | 이름이 비었거나 공백뿐임 | 이름을 입력하라는 안내와 오류 표시를 띄우고 입력창에 초점을 둡니다. | 과제 입력 유지 |
| 이름 수정 | `input` | 오류 안내가 표시된 상태 | 해당 오류 표시를 지웁니다. 다음 버튼을 누르면 다시 검사합니다. | 과제 입력 유지 |
| 마감 선택하기 | `submit` | 이름이 있음 | 양끝 공백을 정리하고 마감 방식 선택으로 이동합니다. | 마감 선택 |
| 마감 방식 변경 | `change` | 마감일 지정 선택 | 날짜 입력을 표시하고 필수 입력으로 바꿉니다. | 마감 선택 유지 |
| 마감 방식 변경 | `change` | 마감일 없이 시작 선택 | 날짜 입력을 숨기고 날짜 값과 관련 오류를 지웁니다. | 마감 선택 유지 |
| 계획 내용 확인하기 | `submit` | 방식 미선택 또는 필요한 날짜 누락 | 빠진 항목의 수정 방법을 표시하고 해당 항목에 초점을 둡니다. | 마감 선택 유지 |
| 계획 내용 확인하기 | `submit` | 필요한 값이 모두 있음 | 입력한 이름·과목·선택한 마감을 요약에 반영합니다. | 내용 확인 |
| 이전 버튼 | `click` | 입력이나 선택을 수정하려 함 | 값을 유지한 채 바로 이전 단계로 돌아갑니다. 수정 후 진행하면 요약도 갱신됩니다. | 이전 단계 |
| 이 계획으로 시작하기 | `click` | 내용 확인 중 | 다시 확인과 계획 확정을 선택할 수 있는 확인 창을 엽니다. | 내용 확인 유지 |
| 다시 확인 또는 Escape | `click` / 키보드 취소 | 확인 창이 열림 | 창을 닫고 입력·선택·요약을 유지합니다. 초점은 원래 버튼으로 돌아갑니다. | 내용 확인 유지 |
| 계획 확정 | `click` | 확인 창이 열림 | 완료 안내, 정리한 계획, 다음 행동을 보여 줍니다. | 완료 |
| 새 계획 세우기 | `click` | 계획 완료 | 이름·과목·선택·날짜·오류·요약·진행 상태를 모두 초기화합니다. | 빈 과제 입력 |

이전 이동과 확인 취소는 수정할 내용을 남기고, 새 계획 세우기는 새 입력을 위해 작성 중인 흐름만 비웁니다. 이미 내 과제에 추가한 항목은 그대로 유지됩니다. 화면에 입력한 내용은 `textContent`로 반영하며 HTML로 해석하지 않습니다.

## 내 과제 목록

계획 완료 → 내 과제에 추가 → 목록에서 다시 열기 → 완료 표시 또는 계속 진행

목록은 마감일이 가까운 순서로 보여 주며, 마감일이 없는 과제는 뒤에 둡니다. ‘전체’, ‘진행 중’, ‘완료’로 범위를 골라 볼 수 있습니다. ‘다시 열기’에서는 과제 이름·과목·마감·현재 상태를 확인하고, 완료로 표시하거나 진행 중으로 되돌릴 수 있습니다.

| 사용자 행동 | 확인할 조건 | 성공 반응과 다른 분기의 반응 | 다음 행동 |
| --- | --- | --- | --- |
| 내 과제에 추가 | 확정한 계획이 있고 같은 이름·과목·마감의 항목이 아직 없음 | 진행 중 항목으로 목록에 추가하고 추가 버튼을 비활성화합니다. | 내 과제 목록 보기 또는 새 계획 세우기 |
| 같은 계획 다시 추가 | 이름·과목·마감이 모두 같은 항목이 이미 있음 | 중복 항목을 만들지 않고 기존 항목을 목록에서 확인하도록 안내합니다. | 목록에서 다시 열기 |
| 전체·진행 중·완료 선택 | 선택한 상태에 해당하는 항목이 있음 | 해당 항목만 목록에 표시합니다. | 과제 다시 열기 |
| 상태 필터 선택 | 목록은 있으나 선택한 상태의 항목이 없음 | 결과가 없다는 안내와 ‘전체 과제 보기’를 표시합니다. | 전체 목록으로 돌아가기 |
| 내 과제 목록 확인 | 추가한 항목이 하나도 없음 | 빈 목록 안내와 ‘첫 계획 세우기’를 표시합니다. | 새 계획 작성 |
| 다시 열기 | 선택한 항목이 목록에 있음 | 저장한 이름·과목·마감·상태를 상세 화면에 표시합니다. | 완료 표시, 진행 중으로 변경, 삭제 또는 닫기 |
| 완료로 표시·진행 중으로 되돌리기 | 상세 화면에서 항목을 보고 있음 | 상세 상태와 목록을 함께 바꾸고 변경 내용을 저장합니다. 현재 필터에 맞지 않으면 해당 항목은 목록에서 빠집니다. | 상태에 맞는 목록 확인 |
| 삭제 선택 | 상세 화면에서 항목을 보고 있음 | 바로 지우지 않고 삭제할지 확인합니다. | 삭제 확정 또는 계속 보관 |
| 계속 보관·Escape | 삭제 확인 중 | 항목과 진행 상태를 그대로 유지합니다. | 상세 내용 확인 또는 목록으로 돌아가기 |
| 삭제 확정 | 삭제 확인 중 | 선택한 항목만 목록에서 제거합니다. 남은 항목이 없으면 빈 목록을 보여 줍니다. | 다른 과제 확인 또는 새 계획 작성 |
| 상세 화면 닫기 | 항목을 확인한 상태 | 목록으로 돌아오고 초점을 목록의 조작 위치로 옮깁니다. | 다음 과제 다시 열기 |

목록은 `localStorage`의 `moabom.tasks.v1`에 저장합니다. 같은 브라우저에서 새로고침해도 항목과 완료 상태를 다시 불러오며, 브라우저의 사이트 데이터를 지우면 목록도 사라집니다. 서버나 계정에 전송하지 않습니다.

브라우저가 저장을 허용하지 않으면 현재 화면에서는 목록을 사용할 수 있도록 두고, 변경 내용이 보존되지 않는다는 안내를 표시합니다. 저장된 목록을 읽을 수 없을 때도 안내를 보여 주며, 읽지 못한 원본을 새 데이터로 덮어쓰지 않습니다.

## 함께 사용할 수 있는 기능

- 과제 적기·마감 확인·완료 표시 탭과 과제 이름의 실시간 미리보기
- 완료 체크·해제, 다시 진행하기, 예시 넣기
- 상단 메뉴를 통한 페이지 내부 이동
- 빈 입력·형식 오류·확인 완료를 구분하는 이메일 형식 확인

미리보기 탭의 과목과 마감일은 예시입니다. 이메일은 형식만 확인하며 저장하거나 전송하지 않습니다.

## 화면과 키보드 조작

768px 이하에서는 메뉴·탭·입력 영역과 버튼을 세로로 배치합니다. 긴 과제 이름은 요약에서 줄바꿈합니다. 오류는 입력창 가까이에 표시하고, 단계가 바뀌면 다음 입력창이나 제목으로 초점을 옮깁니다.

Tab으로 조작 요소를 이동하고 Enter로 입력을 진행할 수 있습니다. 탭은 넓은 화면에서 좌우, 좁은 화면에서 위아래 방향키로 전환합니다. 확인 창에서는 Tab으로 두 버튼을 이동하며 Escape로 취소할 수 있습니다.

실제로 확인한 경로와 결과입니다.

- 정상 경로: 계획 두 개를 확정해 목록에 추가하고, 다시 열었을 때 이름·과목·마감이 일치했습니다. 마감일이 빠른 항목이 먼저 표시됐습니다.
- 중복과 빈 결과: 같은 계획을 추가해도 항목 수가 늘지 않았습니다. 완료한 과제가 없을 때 안내가 표시되고 ‘전체 과제 보기’로 돌아갈 수 있었습니다.
- 상태 변경: 완료로 표시하거나 진행 중으로 되돌리면 상세 내용·목록·개수가 함께 바뀌었습니다. 현재 필터에 해당하지 않는 항목은 목록에서 빠졌습니다.
- 삭제와 취소: 계속 보관하기와 Escape는 항목을 유지했고, 삭제 확정은 선택한 항목만 제거했습니다. 마지막 항목 삭제 후에는 첫 계획을 만드는 안내가 표시됐습니다.
- 보존: 새 계획을 시작해도 기존 목록이 남았습니다. 새로고침 후에도 추가한 항목·완료 상태·삭제 결과가 유지됐습니다.
- 저장 예외: 저장 공간 부족을 재현했을 때 안내와 현재 화면의 목록 조작이 동작했습니다. 잘못된 저장 데이터도 오류 없이 안내하고 원본을 그대로 두었습니다.
- 화면과 기존 기능: 60자 이름을 문자 그대로 표시하고 줄바꿈했습니다. 키보드 이동, 기존 탭·계획 입력·오류·수정·완료·재시작·이메일 확인도 통과했습니다.

검사 중 JavaScript·콘솔 오류와 가로 넘침은 없었습니다. 실제 배포 스크린샷에서도 모바일·데스크톱의 목록, 상세 화면, 삭제 확인이 잘리거나 겹치지 않았습니다. 배포된 HTML·CSS·JavaScript가 저장소 코드와 일치하는 것도 확인했습니다.

## 실행 방법

저장소를 내려받아 `index.html`을 브라우저에서 열면 됩니다. HTML, CSS, JavaScript와 SVG로 구성되어 별도 빌드 과정은 없습니다. 화면 스타일은 `style.css`, 동작은 `script.js`에서 수정할 수 있습니다.
